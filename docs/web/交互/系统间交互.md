# 系统间交互总览

## 通用链路

```
客户端 ──TCP── Gate(GateActor) ──RPC── Login / Global(Friend/Room/Chat/Spectator) / Game(Player/Battle)
```

- 客户端所有消息统一发 Gate，`CNetGateway` 解析 `big_type`/`small_type` 得 `msgId=(big<<16)|small`。
- Gate 按 `big_type` 把消息 RPC 转发给对应 Actor 所在进程，回包 `si_net_send(cid, ...)` 回客户端。
- 服务器主动推送（房间列表刷新、聊天广播、帧命令、战斗结束）也走 `si_net_send` 到对应 CID。

## 消息路由（按 big_type）

| 协议 | big_type | 处理 Actor（承载进程） |
|---|---|---|
| login.proto | AT_LOGIN=101 | LoginActor(Login) |
| friend.proto | AT_FRIEND=102 | FriendActor(Global) |
| room.proto | AT_ROOM=103 | RoomActor(Global) |
| chat.proto | AT_CHAT=104 | ChatActor(Global) |
| battle.proto | AT_BATTLE=203 | BattleActor(Game) |
| spectator.proto | AT_SPECTATOR=204 | SpectatorActor(Global) |

## 跨进程 RPC 关键路径

| 路径 | 机制 |
|---|---|
| Gate → Login/Global/Game | 按 `big_type` 转发 |
| RoomActor(Global) → BattleActor(Game) | `CreateActorRemote(AT_BATTLE)` 创建 + RPC |
| PlayerActor(Game) → FriendActor(Global) | 在线状态通知 RPC |
| SpectatorActor(Global) → BattleActor(Game) | 跨进程订阅帧流 |

## Actor 间消息路由规则

1. 用目标 `PlayerID` 查 Redis 得到 `ActorID`（`player:{playerId} → actorId`）。
2. 用 `ActorID` 路由（`MachineID+PID` 定位进程、`ActorIndex` 定位进程内 Actor）。
3. 优先用消息里带的 / 本地缓存的 `ActorID`；失效（目标离线/迁移）→ 回 Redis 重取。
4. 回包原路返回；超时 RPC 返回 `code=2`（TimeOut）。
