# RealServer C++ 编码规范

> 依据：`document/C++_C.pdf`《高质量 C++/C 编程指南》v1.0（林锐，2001）。
> 本文档是 PDF 规则在本项目内的落地，用于约束 `engine/` 及后续新增的服务器 C++ 代码。

## 0. 适用范围与优先级

1. **优先级**：本项目 `CLAUDE.md` 中的约定（红线）> 本规范（PDF）> 个人习惯。
   两处冲突时，以 `CLAUDE.md` 为准，本规范只补足 PDF 中 `CLAUDE.md` 未覆盖的部分。
2. **生效范围**：`engine/`（框架与基础设施）及后续新增的 C++ 服务器代码。
   生成物（`source/proto-cpp/`、`engine/luacore_generated/`、`build/`、`third_part/`）不在规范内，禁止手改。
3. **机械化 vs 人工**：版式类规则由 `.clang-format` 统一执行；语义类规则（内存、const、命名、
   NULL 检查、Big-Three 等）无法自动完成，需在代码评审中人工把关（见附录审查表）。

## 1. 文件结构（PDF 第 1 章）

| 规则 | 内容 | 落实 |
|------|------|------|
| 1-2-1 | 防止头文件重复引用 | 本项目统一用 `#pragma once`（等效于 `ifndef/define/endif`，已在工程中普遍使用） |
| 1-2-2 | 标准库头文件用 `#include <...>` | 遵循 |
| 1-2-3 | 工程头文件用 `#include "..."` | 遵循（相对路径加载，勿改动 include 顺序，`.clang-format` 已关 `SortIncludes`） |
| 1-2-1(建议) | 头文件只放声明、不放定义（内联函数体等移到 .cpp） | 人工把关 |

## 2. 版式（PDF 第 2 章）—— 已由 `.clang-format` 机械化执行

| 规则 | 内容 |
|------|------|
| 2-1-1 / 2-1-2 | 类声明后、函数定义后加空行；函数内逻辑相关语句不加空行 |
| 2-2-1 | 一行只做一件事（一个变量 / 一条语句） |
| 2-2-2 | `if/for/while/do` 自占一行，执行语句不论多少都加 `{}` |
| 2-3-1 ~ 2-3-7 | 关键字后留空格；函数名后紧跟 `(`；`(` 后 / `)`·`,`·`;` 前不留空格；二元操作符前后留空格；一元操作符（`!` `~` `++` `--` `&`）前后不留空格；`[]` `.` `->` 前后不留空格 |
| 2-4-1 / 2-4-2 | `{` `}` 各自独占一行且对齐，块内缩进 |
| 2-5-1 / 2-5-2 | 行宽 ≤ 100（PDF 建议 70~80，本项目折中）；长表达式在低优先级操作符处换行，操作符放新行之首 |
| 2-6-1 | 修饰符 `*` `&` 紧靠变量名：`char *name;` / `int &x` |
| 2-7-x | 注释准确、与代码同步、必要时才加；块结束可加 `// end of ...` |

## 3. 命名（PDF 第 3 章，与本项目既有约定合并）

本项目沿用 `CLAUDE.md` 既有命名（比 PDF 更具体，含类型提示前缀）：

- 类名带前缀：框架基类 `x*`，管理器 `C*`（如 `CActorMgr`），第三方 `tService*`；类名/函数名大写字母开头。
- 成员变量 `m_` 前缀 + 类型提示：`m_i32Xxx`(int32)、`m_i64Xxx`(int64)、`m_u32Xxx`(uint32)、
  `m_strXxx`(string)、`m_bXxx`(bool)、`m_mapXxx`、`m_stXxx`(struct)。
- 局部变量/参数：小写开头、可拼读；枚举 `E` 前缀（`EActorType_None`）；常量全大写。
- 整数类型统一用 `xBase/xDefine.h` 的 `int8/int16/int32/int64/uint8/uint16/uint32/uint64`，
  **禁止裸 `int/long/short`**（`CLAUDE.md` 红线）。
- 遵循 PDF 3-1-x 共性规则：标识符可拼读、不过短/过长、不用仅大小写区分的相似名、
  局部与全局不重名、变量用名词、函数用动词、互斥语义用反义词（`Get/Set`、`min/max`）。

## 4. 表达式与语句（PDF 第 4 章）—— 人工把关

| 规则 | 内容 |
|------|------|
| 4-1-1 | 运算符多时用括号确定优先级 |
| 4-2-1/2 | 不写过于复杂或多用途的复合表达式 |
| 4-3-1 | 布尔变量不直接与 `TRUE/FALSE/1/0` 比较：写 `if (flag)` / `if (!flag)` |
| 4-3-2 | 整型与 0 比较用 `==` / `!=`：`if (value == 0)` |
| 4-3-3 | 浮点不用 `==`/`!=` 与数字比较，用 `>=`/`<=` + 误差（EPSINON） |
| 4-3-4 | 指针与 `NULL`/`nullptr` 比较用 `==`/`!=`，不写 `if (p)` 误当布尔 |
| 4-4-x | 长循环放最内层；循环内逻辑判断外提 |
| 4-5-1 | 不在 for 循环体内改循环变量；区间用半开半闭 `i < N` |
| 4-6-1/2 | 每个 `case` 结尾加 `break`；保留 `default` 分支 |
| 4-7 | `goto` 少用慎用（本项目基本不用） |

## 5. 常量（PDF 第 5 章）

- C++ 中用 `const`/`constexpr` 取代 `#define` 宏常量（规则 5-2-1）。
- 多次出现的数字/字符串用含义直观的常量表示（规则 5-1-1）。
- 对外公开常量放头文件，否则放定义文件头部；相关常量用表达式关联（如 `DIAMETER = RADIUS * 2`）。

## 6. 函数设计（PDF 第 6 章）

| 规则 | 内容 |
|------|------|
| 6-1-1 | 参数书写完整（类型 + 名字）；无参数写 `void` |
| 6-1-2 | 参数命名恰当、顺序合理（目的在前、源在后） |
| 6-1-3 | 仅作输入的指针参数加 `const` |
| 6-1-4 | 非内部数据类型输入参数用 `const &` 传递 |
| 6-1-1(建议) | 参数个数尽量 ≤ 5 |
| 6-2-1 | 不省略返回值类型；无返回值写 `void` |
| 6-2-3 | 正常值与错误标志分离（错误码走 return，结果走输出参数） |
| 6-3-1 | 函数入口用 `assert` 检查参数有效性 |
| 6-3-2 | `return` 不返回指向栈内存的指针/引用 |
| 6-5-1/2 | 用 `assert` 捕获「不应该发生」的非法情况，不用于处理必然的错误 |

## 7. 内存管理（PDF 第 7 章）

| 规则 | 内容 |
|------|------|
| 7-2-1 | `new`/`malloc` 后立即检查是否为 `NULL` |
| 7-2-2 | 数组和动态内存赋初值（含零值）；`char buf[N] = {0};`（`CLAUDE.md` 红线） |
| 7-2-3 | 避免数组/指针下标越界（尤其 ±1） |
| 7-2-4 | `new/delete`、`malloc/free` 必须配对，不混用 |
| 7-2-5 | `free`/`delete` 后立即置 `NULL`/`nullptr`，杜绝野指针 |
| 7-8 | 动态对象用 `new/delete`（保证构造/析构），C 接口才用 `malloc/free` |

## 8. 类设计（PDF 第 9~11 章）

- **Big-Three**（9.x）：含裸指针/动态内存的类须显式实现（或删除）构造函数、析构函数、拷贝构造、赋值函数；
  赋值函数四步：①检查自赋值 ②释放旧资源 ③分配新资源并复制 ④返回 `*this`。
- **继承/组合**（10.x）：`is-a` 用继承，`has-a`/`part-of` 用组合，不可为省事乱继承。
- **const 正确性**（11.1）：不修改数据成员的函数声明为 `const` 成员函数；输入引用参数加 `const`。
- **析构虚化**（9.8）：有继承关系时基类析构函数应为 `virtual`。

## 附录：与 PDF 的显式差异（工程折中）

| 项 | PDF | 本项目 | 理由 |
|----|-----|--------|------|
| 行宽 | 70~80 | 100 | 长日志语句 / 中文注释更友好 |
| 头文件保护 | `ifndef/define/endif` | `#pragma once` | 现有代码普遍采用，等效 |
| 命名 | 泛 Windows 命名（`m_/g_/s_` 前缀） | 保留 `CLAUDE.md` 的类型提示前缀（`m_i32*` 等） | 既有约定更具体，`CLAUDE.md` 优先 |
| 整数类型 | `int`/`long` | `int8/…/uint64` 别名 | `CLAUDE.md` 红线 |
| 宏常量 | `const` 取代 `#define` | 保留必要 `#define`（如协议 ID），其余用 `const`/`constexpr` | 工程兼容 |

## 附录：代码审查表（语义项，人工把关）

代码评审时逐条核对（对应 PDF 附录 A）：

- [ ] 内存：`new/malloc` 后是否检查 `NULL`；`free/delete` 后是否置空；是否配对/混用；下标是否越界。
- [ ] 野指针：指针变量创建即初始化；释放后置空；不返回栈内存。
- [ ] const：只读指针/引用参数加 `const`；不修改成员的函数声明为 `const`。
- [ ] if 比较：布尔不比较 `TRUE/1/0`；浮点不用 `==`；指针用 `== NULL`。
- [ ] switch：每个 `case` 有 `break`，有 `default`。
- [ ] 常量：多次出现的魔数/字符串用常量；C++ 用 `const` 不用宏常量。
- [ ] 函数：参数完整带名字；入口 `assert` 检查；返回类型不省略；返回不指向栈。
- [ ] 类：Big-Three 完整；赋值函数四步齐全；有继承时析构 `virtual`；继承/组合关系正确。
- [ ] 命名：无裸 `int/long`；标识符可拼读；成员带 `m_` 前缀。
- [ ] 缓冲区：`char buf[N]` 必须 `= {0}` 零初始化。
